# Session Log — March 18, 2026

## Summary (for human)

**What you asked:** Build the full auth API backend based on the `auth.md` spec.

**What I implemented:** A complete FastAPI backend with 10 auth endpoints:
- Sign in / Sign up (email + password)
- Google OAuth login
- Forgot password → verify email → reset password (6-digit code flow)
- Resend verification code (30s cooldown)
- Refresh token rotation
- Logout (revokes tokens)
- Get current user (`/auth/me`)

All endpoints match the request/response shapes defined in `api-document/auth/auth.md`. Password validation enforces 8+ chars with upper, lower, digit, and special character. Verification codes expire after 6 minutes.

### Architecture Decisions
- **Async everywhere**: SQLAlchemy async sessions with `asyncpg` driver
- **Provider field on User**: `"email"` or `"google"` — Google users have no `password_hash`
- **Refresh token rotation**: Old refresh token is revoked when a new one is issued
- **Logout**: Revokes all refresh tokens for the user
- **Verification codes**: Stored in DB with expiry, cleaned up after successful verification
- **Auto table creation**: `Base.metadata.create_all` runs on startup via lifespan (Alembic recommended for production migrations)

### Database (PostgreSQL)
- `users` — UUID PK, unique email index, provider, is_verified flag
- `verification_codes` — 6-digit codes with type (signup/reset) and expiry
- `refresh_tokens` — linked to user, revocable, with expiry

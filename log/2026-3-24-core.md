# Core Homescreen APIs — March 24, 2026

## What We Built

4 new endpoints that power the main home screen — these are what the frontend buttons actually call.

## New Endpoints

| # | Method | Endpoint | What it does | Maps to frontend |
|---|--------|----------|-------------|-----------------|
| 1 | GET | `/recommendations/combo?date=&mealType=` | Returns personalized meal combos per dining hall, filtered by user allergens/dislikes, optimized toward calorie targets | Date pills + Hall cards |
| 2 | GET | `/goals/daily?date=` | Returns daily nutrition progress — goal vs consumed for calories, protein, carbs, fat | Today's Goals card |
| 3 | GET | `/menus/summary?date=` | Returns top 5 recommended items per dining hall with dietary icons, filtered by preferences | Hall card details |
| 4 | POST | `/meals/log` | Logs a meal — creates/finds a meal_log for the date+mealType, adds food items with snapshotted nutrition | "Log This Meal" button |

All 4 require JWT auth.

---

## How Each Endpoint Works

### GET /recommendations/combo

1. Loads user preferences (allergens, dislikes, calorie targets)
2. Finds menu snapshots for the given date + meal type (auto-infers meal type from time of day if not specified)
3. Gets all foods from each dining hall's snapshot with nutrition data
4. Filters out foods matching user's allergens or dislikes
5. Picks a combo of foods that approaches 1/3 of daily calorie target
6. Returns one combo per dining hall

### GET /goals/daily

1. Loads user's nutrition targets from `user_preferences` (defaults to 2000cal / 120g protein / 250g carbs / 65g fat if not set)
2. Sums all `meal_log_items` for the given date via `meal_logs`
3. Returns goal vs consumed for each macro

### GET /menus/summary

1. Loads all menu snapshots for the date across all dining halls
2. Gets food items with nutrition for each hall
3. Filters by allergens/dislikes
4. Attaches dietary icons (vegan, halal, etc.) to each food
5. Returns top 5 items per hall sorted by calories

### POST /meals/log

1. Finds or creates a `meal_log` row for the user + date + meal type
2. For each item: if `foodId` is provided and no nutrition sent, looks up from `food_nutrition` table
3. Creates `meal_log_item` rows with snapshotted nutrition values
4. Returns the meal log ID
